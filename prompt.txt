I'm a Software Engineering student with a socket programming assignment:

"Write a program that creates a socket on any port between 6000 and 65,535
and returns the local computer's system time. Be ready to present and hand
it in."

The course slides cover Berkeley/WinSock sockets in C over TCP/IP, but I
must implement it in Java. Please build the following.

REQUIREMENTS
1. A TCP time server using java.net.ServerSocket:
   - Listens on a configurable port (default 6000, validated to be in the
     range 6000-65535; reject anything else with a clear message).
   - Runs forever as an iterative server: accept a client, send the current
     system time of the machine the server runs on, close that client
     connection, then go back to accepting the next client.
   - Sends the time as a readable text line, e.g. "2026-10-01 14:32:05 EAT",
     using java.time (ZonedDateTime + DateTimeFormatter).
   - Logs each client's IP address and port when it connects.
2. A TCP client using java.net.Socket:
   - Takes the server IP/hostname and port as command-line arguments
     (like argv[1] in the slides), connects, reads the time, prints it, and
     closes the socket.
3. Proper error handling: invalid port, port already in use
   (BindException), connection refused, unknown host, and I/O errors.
   Use try-with-resources so sockets always close.
4. Optional bonus: a UDP version (DatagramSocket / DatagramPacket) of the
   same server and client, so I can compare TCP and UDP.

CODE STYLE
- Plain Java 17+, no external libraries, runnable with javac and java.
- Small, clearly commented files: TimeServer.java and TimeClient.java
  (plus UdpTimeServer.java / UdpTimeClient.java if you do the bonus).
- Comments should note which step of the socket algorithm each line
  represents.

ALSO GIVE ME
1. A table mapping each C/WinSock call from my slides to its Java
   equivalent: socket(), bind(), listen(), accept(), connect(),
   send()/recv(), closesocket(), htons()/htonl(), inet_addr(),
   gethostbyname(), WSAStartup()/WSACleanup() (say which ones Java hides
   and why).
2. Exact commands to compile and run the server and client, including
   testing on two machines in the same network and testing with
   localhost.
3. How to verify it works (e.g. using telnet/nc to connect to the server,
   and optionally Wireshark to see the TCP handshake).
4. A short explanation I can use in my presentation covering: why TCP, what
   the server does step by step, the difference between the listening
   socket and the socket returned by accept(), and why Java doesn't need
   network byte order conversion when sending text.
5. Three likely questions a lecturer might ask, with answers.
